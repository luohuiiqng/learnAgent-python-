# 评估规范

本文件规定如何判断一个知识点是否掌握。教学和评估都按这里执行，进度记录在 `docs/学习进度.md`。

## 1. 掌握层级

| 层级 | 名称 | 达标条件 |
|---|---|---|
| L0 | 未接触 / 未评估 | 默认状态。跟着教程写过代码，但还没有测过，也算 L0 |
| L1 | 知道 | 能用自己的话准确说出概念是什么 |
| L2 | 理解 | 能解释设计原因；预测代码输出题全部答对 |
| L3 | 会用 | 闭卷、不用 AI，独立写出代码，通过全部测试用例（包括边界情况） |
| L4 | 会排错 | 在埋了 bug 的代码里，找出所有 bug，说清原因并修复 |
| L5 | 能迁移 | 变式题或设计题答得好，经得起至少三层连续追问，能说出取舍 |

层级必须逐级通过，不能跳级。前一级没有达标，就不测下一级。

### 目标层级

| 知识点类型 | 目标层级 |
|---|---|
| 面试高频考点（标 ★） | L5 |
| 核心知识点（后续阶段会直接用到） | L4 |
| 工具类知识点（ruff、docker 命令等） | L3 |
| 了解即可的知识点 | L1 |

## 2. 题型与对应层级

| 题型 | 测试层级 | 做法 |
|---|---|---|
| 口述 | L1 | 用自己的话解释概念，不能照抄定义 |
| 追问“为什么” | L2、L5 | 连续追问，直到回答不上来为止 |
| 预测输出 | L2 | 先写下预测的结果，再运行代码核对 |
| 闭卷编码 | L3 | 给出需求和函数签名；测试用例由教练准备，事先不公开 |
| 找 bug | L4 | 一段能运行但结果有错的代码，里面埋 2 到 3 个原因不同的 bug |
| 变式题 | L5 | 同一个知识点放到新场景里 |
| 设计题 | L5 | 开放问题，看考虑是否全面，取舍是否合理 |
| 模拟面试 | 阶段验收 | 综合出题，按面试官的方式追问 |

## 3. 单题评分（0 到 3 分）

| 分数 | 标准 |
|---|---|
| 3 | 完全正确，并能解释原因 |
| 2 | 基本正确，但不完整，或者需要一次提示 |
| 1 | 方向对，但有关键错误，或者需要多次提示 |
| 0 | 不会，或者方向错误 |

- 给过提示的题，最高 2 分。
- 查过资料的题，标注“查资料”，最高 2 分。
- 答案由 AI 生成的题，作废，下次重测。

**达标判定**：一个层级的题目每道都在 2 分及以上，并且平均分不低于 2.5，才算达到这个层级。

**评分顺序**：先给分数和扣分理由，再讲正确答案。评分按面试官的标准，不放宽。

## 4. 复测规则（间隔复习）

1. 知识点达到目标层级后，7 天后复测一次，再过 14 天复测第二次。
2. 每次复测只考目标层级的 1 到 2 道新题，不重复用旧题。
3. 复测通过，状态记为“已巩固”；两次都通过后，不再安排复测。
4. 复测不通过，层级降一级，状态改为“需复习”，并记入错题本。
5. 每次会话开始时，先处理所有到期的复测，再学新内容。

## 5. 阶段验收

一个阶段同时满足下面三条，才能进入下一阶段：

1. 本阶段所有 ★ 和核心知识点都达到目标层级。
2. 阶段交付物通过学习计划中的验收标准。
3. 模拟面试得分不低于 70 分（满分 100）。

### 模拟面试评分（满分 100）

| 维度 | 分值 | 看什么 |
|---|---|---|
| 正确性 | 30 | 有没有事实错误 |
| 深度 | 30 | 能不能讲清原理，经得起几层追问 |
| 工程思维 | 25 | 是否考虑边界情况、故障、成本、取舍 |
| 表达 | 15 | 是否先说结论，条理是否清楚 |

## 6. 诚信约定

- 做测试题时关闭 AI 补全，不查资料。如果查了，主动说明。
- 不会就说“不确定”，不要猜。蒙对的题不能反映真实水平。
- 报错时贴完整的错误信息，不要只描述现象。

## 7. 记录格式

每次评估后，在 `docs/学习进度.md` 中更新以下内容：

1. 知识点表中的“当前层级”“状态”“最近评估”“下次复测”。
2. 在评估记录中追加一行：日期、知识点编号、题型、得分、结论。
3. 新出现的错误，记入错题本。
4. 在会话日志中写一行本次会话的摘要。
