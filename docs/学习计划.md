## 一、招聘市场现在要什么

### 1.1 一份大厂岗位要求原文

腾讯 2027 届校招首次把 Agent 开发工程师、AI 应用工程师、AI 全栈工程师设为独立岗位，覆盖全部六大事业群（[来源](https://www.cnblogs.com/itech/p/22482094)，数据截至 2026-08-14）。Agent 开发工程师的要求可以概括为：

| 类别 | 内容 |
|---|---|
| 职责 | 多 Agent 协作框架、任务规划与调度、工具调用引擎；记忆系统与决策机制；评测与质量保障体系，包括性能和成本管控 |
| 必备 | 一门主流语言加扎实的数据结构与算法；深入理解 Planning / Memory / Tool Use / Reflection；有 LangGraph、AutoGen、CrewAI 等框架的实际搭建经验；会写高质量的系统提示词和工具描述 |
| 加分 | 多 Agent 和复杂工作流经验；Agent 评测体系经验；RAG、向量检索、知识图谱；开源项目、技术博客、作品展示 |

AI 全栈工程师岗位把“熟练使用 Cursor、Claude Code 等 AI 编程工具”写成了必备要求。

### 1.2 海外市场的统计

Andela 分析了近 5 万份招聘信息，归纳出“LLM 应用工程师”需要四类能力：模型集成、Harness（包在模型外面的工程代码）、评测、治理与安全护栏。普通后端工程师通常缺后三类（[来源](https://codersera.com/blog/hire-llm-application-engineer-2026/)）。同一篇文章引用 Indeed 的数据：受 AI 影响最大的职业里，初级岗位的占比从 2021 年的 29% 降到 2026 年的 10%（美国数据）。

### 1.3 对你的含义

1. 只会调 API 写 Prompt 已经不够。岗位要求里反复出现的是 RAG 闭环、多 Agent 编排、评测、成本与安全。
2. 评测能力是分水岭，所以每个项目都要有评测数据。
3. 初级岗位在减少，简历要按“有经验的工程师转方向”来写，突出工程能力加 AI 能力。
4. 作品集比证书重要。每个项目放到 GitHub，并写一篇复盘博客。

## 三、分阶段计划

每个阶段的验收标准没有达到，不进入下一阶段。知识点的拆分和当前层级见 `docs/学习进度.md`。

### P0 Python 进阶与后端基础（第 1-3 周，11/09 - 11/29）

**学什么**
- Python 核心：数据模型、推导式、生成器与 `yield`、装饰器、上下文管理器、类型标注
- 和 C++ 的关键差异：引用语义、可变与不可变对象、GIL、鸭子类型、异常处理习惯
- `asyncio`：事件循环、`async/await`、`gather`、超时与取消，对照 `QEventLoop`
- Pydantic v2：数据校验与序列化
- 工程化：`uv`、`pyproject.toml`、`ruff`、`pytest`、日志
- 后端：FastAPI（路由、依赖注入、后台任务、SSE 流式响应）、PostgreSQL 与 SQLAlchemy、Redis 基础
- Docker 与 docker-compose；Linux 常用命令

**面试必问**：GIL 对 IO 密集和 CPU 密集任务的影响分别是什么？协程和线程有什么区别？生成器为什么能做流式输出？

**交付物**：异步 FastAPI 小服务，提供增删改查接口，连 PostgreSQL，docker-compose 一键启动，带 pytest 测试。

**验收标准**：不查资料写出异步爬虫，用 `asyncio.gather` 并发请求，带超时和重试。

### P1 大模型原理与模型集成（第 4-6 周，11/30 - 12/20）

**原理（第 4 周，达到面试深度）**
- Tokenizer（BPE）、Embedding、自注意力、多头注意力、RoPE、RMSNorm、FFN
- Decoder-only 与 Encoder-only 的区别和适用场景
- 解码策略（greedy、temperature、top-p）与幻觉成因
- KV Cache 原理与显存估算；长上下文的代价
- MoE 基本思想；推理模型的特点
- 训练流程概览：预训练 → SFT → RLHF/DPO
- 结合 `transform的最简实现/` 逐行讲解

**模型集成（第 5-6 周）**
- 至少调通 DeepSeek、通义千问和本地 Ollama
- 结构化输出：JSON Schema、Pydantic 校验、解析失败重试
- 工具调用、SSE 流式输出、并行工具调用
- 可靠性：指数退避重试、超时、限流、降级到备用模型
- 成本：token 计费、Prompt 缓存、按任务难度选模型
- 多厂商抽象层

**面试必问**：Attention 为什么除以 √d？KV Cache 节省了什么、代价是什么？怎么保证稳定输出合法 JSON？每月 100 万次调用的功能怎么估算并降低成本？

**交付物**：`llm_gateway` 模块，统一封装多家模型，支持结构化输出、流式、重试、降级，记录每次调用的 token 数和费用。

**验收标准**：只改配置就能切换模型；主模型超时时自动降级到备用模型。

### P2 Prompt 与上下文工程、Agent 核心机制（第 7-8 周，12/21 - 2027/01/03）

- Prompt 工程：角色、约束、few-shot、思维链；工具描述的写法
- 上下文工程：每次调用时系统提示、历史、检索内容、工具结果、记忆各放什么、放多少（[参考](https://sourcegraph.com/blog/context-engineering)）
- 上下文管理：滑动窗口、摘要压缩、token 预算
- Agent 四大机制各手写一遍：Tool Use（仓库已有 ReAct 和 Function Calling 两版）、Planning、Reflection、Memory
- 可靠性：最大步数、死循环检测、工具错误反馈、高风险操作人工确认

**面试必问**：ReAct 和 Function Calling 的区别？Agent 死循环怎么处理？上下文快满了怎么办？长期记忆怎么设计？

**交付物**：不依赖框架的 `mini_agent`，实现四大机制，附复盘博客。

**验收标准**：能画出 Agent 完整循环图，说清每个环节可能出什么故障、怎么处理。

### P3 RAG 深入（第 9-12 周，01/04 - 01/31）：项目 1 核心

- 文档解析：PDF（含表格和 OCR）、Word、Markdown、网页
- 切分：固定长度、递归、语义切分、父子块
- Embedding 选型、维度与成本
- 向量库：Milvus 或 pgvector 深入其一；HNSW、IVF 原理
- 检索：BM25 与向量混合、RRF 融合、Rerank、元数据过滤
- 查询优化：查询改写、HyDE、多查询、问题拆解
- 进阶：GraphRAG 与知识图谱、Agentic RAG
- 生成：引用标注、拒答、减少幻觉

**面试必问**：RAG 效果差按什么顺序排查？切分大小怎么定？为什么要 Rerank？什么时候长上下文就够了？

**交付物**：项目 1 v1 企业知识库问答。FastAPI 后端加简单前端，支持上传、增量索引、流式回答和引用标注；混合检索加 Rerank，做消融实验比较召回率。

**验收标准**：每个回答能追溯到原文段落；消融实验有具体数字。

### P4 评测、安全护栏、可观测性（第 13-14 周，02/01 - 02/14）

春节（2027-02-06）后留一周缓冲（02/15 - 02/21）。

- 评测：黄金数据集；确定性检查与 LLM 打分（先和人工标注校准）；多次运行衡量波动；设定阈值
- 工具：RAGAS、promptfoo（[选型参考](https://www.cnblogs.com/qiniushanghai/p/19712865)）
- 评测接入 CI，分数下降不允许合并
- 安全：直接与间接 Prompt 注入、工具最小权限、输出校验、PII 脱敏、审计日志
- 可观测性：Langfuse 或 OpenTelemetry；功能级成本、延迟、拒答率

**面试必问**：通过率从 94% 到 96% 能直接上线吗？检索文档里藏着“忽略之前的指令”怎么防？每次调用该记录什么、不该记录什么？

**交付物**：项目 1 v2，200 条以上评测集、CI 评测关卡、链路追踪、注入防护，附评测报告。

**验收标准**：能用数字讲清做了什么优化、提升多少、花了多少钱。

### P5 LangGraph、多 Agent、MCP（第 15-19 周，02/22 - 03/28）：项目 2

- LangGraph：State、节点与边、条件路由、Checkpoint、Human-in-the-loop、流式、子图
- 多 Agent：Supervisor、Handoff、层级式；什么时候不需要多 Agent
- 了解 AutoGen、CrewAI、OpenAI Agents SDK 的取舍
- MCP：自写 MCP Server，在 Agent 中作为 Client 接入
- Docker 代码执行沙箱
- Agent 评测：任务成功率、轨迹评测、单任务成本和步数
- 成本路由：简单任务用便宜模型，复杂任务升级

**面试必问**：为什么选 LangGraph？多 Agent 怎么通信、冲突怎么处理？执行中途崩溃怎么恢复？怎么评测 Agent？

**交付物**：项目 2 多 Agent 研究分析助手。规划 Agent 拆解任务，搜索 Agent 和数据分析 Agent（沙箱执行代码）分别执行，报告 Agent 汇总；工具由自写 MCP Server 提供；高风险操作人工确认；支持断点恢复；有评测集和成本统计。

**验收标准**：能现场演示，并讲清一次失败案例的排查过程。

**2027-03-15 开始投递**：简历 v1 写项目 1 和项目 2，先投中小公司练手，再投目标公司。

### P6 推理部署与微调（第 20-22 周，03/29 - 04/18）

- vLLM：PagedAttention、连续批处理、吞吐与延迟权衡、OpenAI 兼容接口
- 量化：GGUF、AWQ、GPTQ；INT4 与 INT8 的影响
- 显存估算：参数量、KV Cache、并发数
- LoRA / QLoRA：用 LLaMA-Factory 或 Unsloth 做一次 SFT，与 RAG 方案对比
- RAG、微调、两者结合分别适用于什么场景

**面试必问**：7B 模型 FP16 推理大约需要多少显存？vLLM 为什么快？LoRA 原理是什么？

**交付物**：在远程 GPU 机器上用 vLLM 部署量化模型，压测出 QPS 和延迟曲线，接入项目 1。

### P7 Qt/C++ 端侧 AI 助手（第 23-26 周，04/19 - 05/16）：项目 3

- llama.cpp：C++ API、GGUF 加载、流式生成、量化等级对比
- Qt 客户端：流式 Markdown 渲染、多会话管理、远程与本地两种模式
- C++ 实现 MCP Client
- 端侧约束：内存、首 token 延迟、tokens/s、功耗

**交付物**：项目 3 Qt AI 桌面助手。有网调用项目 1、2 的后端，离线切换到 llama.cpp 本地模型；附不同量化等级的内存、速度、质量对比报告。

**目标岗位**：AI 客户端、端侧 AI、智能座舱（例如博世有大模型岗位写明车载 AI 经验优先，[来源](https://cn.indeed.com/q-ai-%E5%B7%A5%E7%A8%8B%E5%B8%88-%E8%81%8C%E4%BD%8D.html)）。
