## 1. 阶段交付物：笔记服务

写一个异步 FastAPI 小服务，提供“笔记”的增删改查接口，数据存在 PostgreSQL，用 docker compose 一键启动 app 和 postgres，带 pytest 测试。

项目放在仓库根目录下新建的 `P0_project_notes/` 目录里，自己从零写，可以查文档，不要让 AI 生成代码。

### 1.1 功能需求

一篇笔记有这些字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 主键，数据库自动生成 |
| `title` | str | 必填，1 到 100 个字符 |
| `content` | str | 可选，默认空字符串，最长 10000 个字符 |
| `tags` | list[str] | 可选，默认空列表，最多 10 个 |
| `created_at` | datetime | 创建时间，服务端生成，带时区（UTC） |
| `updated_at` | datetime | 最后修改时间，每次修改时更新 |

- 列表接口支持分页（`limit` 默认 20、最大 100，`offset` 默认 0）和按标题关键字搜索（`q`，不区分大小写）。
- 列表按 `id` 降序（新的在前），响应里带满足条件的总数 `total`。
- 修改用 `PATCH`，只更新请求里出现的字段。
- 所有错误响应的格式统一，至少包含一个可读的 `detail` 字段。

`tags` 可以用 PostgreSQL 的 `ARRAY(String)` 或 `JSONB` 存，也可以拆一张标签表做多对多。写进 README，说明为什么这样选。

### 1.2 接口列表

| 方法 | 路径 | 成功状态码 | 说明 |
|---|---|---|---|
| `GET` | `/health` | 200 | 返回 `{"status": "ok", "db": "ok"}`，要真的查一次数据库（例如 `SELECT 1`）；数据库连不上时返回 503 |
| `POST` | `/notes` | 201 | 请求体 `NoteCreate`，返回 `NoteOut` |
| `GET` | `/notes` | 200 | 查询参数 `limit`、`offset`、`q`，返回 `{"items": [NoteOut, ...], "total": int}` |
| `GET` | `/notes/{note_id}` | 200 | 不存在返回 404 |
| `PATCH` | `/notes/{note_id}` | 200 | 请求体 `NoteUpdate`（所有字段可选），不存在返回 404 |
| `DELETE` | `/notes/{note_id}` | 204 | 不存在返回 404 |

请求体字段不合法（标题为空、超长、`limit=1000` 等）时返回 422，这一点 FastAPI + Pydantic 会自动处理。

### 1.3 技术要求

**数据库访问：从下面两种方案里选一种**，在项目 README 里写清选了哪种、为什么。

| | 方案 A：async SQLAlchemy（推荐） | 方案 B：同步 Session，放在线程池里跑 |
|---|---|---|
| 写法 | `create_async_engine`、`async_sessionmaker`、`AsyncSession`，路由函数写 `async def`，数据库调用前加 `await` | `create_engine`、`sessionmaker`、`Session`，路由函数写普通 `def`，FastAPI 自动把它放到线程池执行 |
| 连接串 | `postgresql+psycopg://...`（psycopg 3 同时支持同步和异步，本机已装，**不用装 asyncpg**；已在本机验证可用）。想用 asyncpg 也可以：`pip install asyncpg`，连接串改成 `postgresql+asyncpg://...` | `postgresql+psycopg://...` |
| 额外的包 | SQLAlchemy 的 async 扩展依赖 `greenlet`（本机已装 3.4.0）。测试想用 SQLite 时要 `pip install aiosqlite` | 不需要 |
| 优点 | 和 asyncio 生态一致：后面调大模型 API、SSE 流式都是 async，同一个服务里不用混两种模型；不占线程池 | 写法和第七课完全一样，好调试；不会出现忘写 `await`、在 async 函数里误调同步阻塞代码的问题 |
| 缺点 | 懒加载的关系属性不能直接访问（会报 `MissingGreenlet`），要用 `selectinload` 提前加载；出错时调用栈更难读 | 并发受线程池大小限制（默认 40 个线程）；如果在 `async def` 路由里调用同步 Session，会阻塞整个事件循环 |

两种方案都要满足：

- **依赖注入获取 Session**：写一个 `get_session` 依赖（生成器，`yield` 一个 Session），每个请求一个 Session，请求结束关闭。路由函数通过 `Depends(get_session)` 拿到 Session，不要用全局 Session。
- **engine 在 lifespan 里创建**，挂到 `app.state` 上，关闭时 `dispose()`。方案 A 尤其要这样做：async 连接属于创建它的事件循环，在模块顶层创建 engine，测试里很容易出现 “attached to a different loop” 之类的错误。
- **Pydantic 模型和 ORM 模型分开**：`NoteCreate`、`NoteUpdate`、`NoteOut` 是 Pydantic 模型；`NoteOut` 设置 `model_config = ConfigDict(from_attributes=True)`，可以直接从 ORM 对象转换。`PATCH` 用 `body.model_dump(exclude_unset=True)` 拿到客户端实际传了的字段。
- **配置走环境变量**：至少 `DATABASE_URL`。可以直接读 `os.environ`，也可以用 `pydantic-settings`（本机已装）。代码里不出现密码；仓库里放 `.env.example`，不放 `.env`。
- **建表**：可以在 lifespan 里 `create_all`，加分项是用 Alembic。
- **不允许拼接 SQL**：所有查询用 ORM 或 `text()` + 绑定参数。
- **事务**：写操作出错时回滚，不留下改了一半的数据。

**Docker**：

- 项目根目录有 `Dockerfile`（`python:3.13-slim`，先装依赖再复制代码，非 root 用户运行，exec 形式的 `CMD`）和 `.dockerignore`（至少排除 `.env`、`.venv/`、`__pycache__/`、`.git/`）。
- `docker-compose.yml` 包含 `app` 和 `postgres` 两个服务：postgres 有 healthcheck 和命名数据卷；app 用 `depends_on: condition: service_healthy` 等数据库就绪；app 里的 `DATABASE_URL` 主机名写 `postgres`。
- `requirements.txt` 固定版本号。容器里要装 `psycopg[binary]`（自带 libpq，不用在镜像里装系统库）。

**测试（pytest）**：

- 至少覆盖：每个接口的正常情况；404；422（标题为空、标题超长、`limit` 越界）；`PATCH` 只改传入的字段；分页和搜索的结果与 `total`；删除后再查返回 404。
- 测试之间互不影响：每个测试开始时数据是干净的（例如测试前清表，或者每个测试用独立的库）。
- 测试用 `fastapi.testclient.TestClient`，写成 `with TestClient(app) as client:`，这样会执行 lifespan。方案 A 也可以直接用 TestClient，测试函数本身不用是 async。如果想写 async 测试函数，anyio 自带的 pytest 插件（`@pytest.mark.anyio`）本机可以直接用，或者 `pip install pytest-asyncio`。
- 测试连哪个数据库：推荐连 compose 里的 PostgreSQL 的独立测试库，和生产环境行为一致；用 SQLite 会遇到 `ARRAY`、`JSONB`、大小写不敏感搜索（`ILIKE`）等差异，要自己处理。

### 1.4 目录结构建议

```

│   ├── __init__.py

├── tests/
│   ├── conftest.py      # client fixture、清表
│   ├── test_health.py
│   └── test_notes.py

├── .dockerignore
```

### 1.6 加分项

不影响是否通过，但每一项都是面试时可以讲的点：

- **Redis 缓存**：compose 里加 redis 服务；`GET /notes/{id}` 先查 Redis，没命中再查数据库并写缓存（设 TTL）；`PATCH` 和 `DELETE` 后删除对应的缓存。Redis 挂掉时服务照常工作，只是不走缓存。用 `redis.asyncio`。能说出“先更新数据库再删缓存”这个顺序的理由。
- **结构化日志**：每个请求输出一行 JSON 日志，包含方法、路径、状态码、耗时（毫秒）、请求 ID；请求 ID 从 `X-Request-ID` 请求头读，没有就生成一个，并放进响应头。用标准库 `logging` 写一个 JSON Formatter 即可（`structlog` 本机没装，想用要 `pip install structlog`）。
- **ruff 通过**：`ruff check .` 和 `ruff format --check .` 没有报错（本机没装，`pip install ruff`），配置写在 `pyproject.toml`。
- **Alembic 迁移**：不用 `create_all`，用 Alembic 建表；容器启动时先执行 `alembic upgrade head`。
- **按用户限流**：用 Redis 做固定窗口限流，超限返回 429 并带 `Retry-After` 响应头。

## 2. 阶段验收题：异步爬虫

闭卷完成：不查资料、不用 AI，限时 90 分钟（函数和 `main()` 约 45 分钟，测试约 45 分钟）。只能看 Python 自带的 `help()`。

### 2.1 题目

写一个函数，并发抓取一组 URL：

```python
async def fetch_all(
    urls: list[str],
    *,
    concurrency: int = 5,
    timeout: float = 5.0,
    retries: int = 2,
) -> list[FetchResult]:
    ...
```

要求：

1. 用 `httpx.AsyncClient` 发请求，所有请求共用一个 client。
2. 用 `asyncio.gather` 并发执行；同一时刻最多 `concurrency` 个请求在进行。
3. 每次请求的超时为 `timeout` 秒。
4. 失败时重试，最多重试 `retries` 次（也就是最多请求 `retries + 1` 次），两次重试之间等待一段时间，等待时间逐次增加（指数退避）。
5. 只对“值得重试”的失败重试：超时、连接错误、HTTP 5xx、429。HTTP 4xx（429 除外）不重试，直接算失败。
6. 一个 URL 最终失败，不影响其他 URL；函数不抛异常。
7. 返回结果的顺序和输入的 `urls` 顺序一致。
8. `FetchResult` 自己定义（dataclass 或 Pydantic 模型），至少包含：`url`、是否成功、HTTP 状态码（没有响应时为 `None`）、响应内容长度或错误信息、实际尝试次数、耗时。
9. 写一个 `main()`：抓取 10 个以上 URL，打印每个结果和总耗时。
10. 用 pytest 写测试，不访问真实网络（用 `httpx.MockTransport` 或自己起一个本地服务），覆盖：全部成功、5xx 后重试成功、超过重试次数后失败、4xx 不重试、超时、并发数不超过 `concurrency`、结果顺序。

注意：本机有系统代理，测试本地服务时要处理 `NO_PROXY` 或给 `AsyncClient` 传 `trust_env=False`。

### 2.2 评分要点
